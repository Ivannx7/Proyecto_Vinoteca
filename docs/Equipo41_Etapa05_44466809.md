## 1. Aporte realizado
Diseño, refactorización y migración de la suite de procedimientos almacenados del sistema de la vinoteca (que incluye sp_registrar_venta, sp_registrar_pago, sp_actualizar_stock, sp_actualizar_precio_vino y sp_eliminar_registro) desde MySQL hacia SQL Server Express.

Implementación de la lógica procedural en T-SQL utilizando control de flujo avanzado (IF...ELSE), consultas parametrizadas, control de sesiones (SET NOCOUNT ON) y captura de identidad con SCOPE_IDENTITY().

Incorporación de mecanismos de control de errores mediante bloques estructurados BEGIN TRY...BEGIN CATCH y la instrucción THROW, asegurando la validación rigurosa de reglas de negocio e integridad referencial.

Desarrollo y validación del script completo de pruebas y ejecución con llamadas mediante EXEC para simular operaciones transaccionales reales.

## 2. Decisiones en las que participé

Estandarización de procedimientos transaccionales: Se decidió que la lógica de negocio pesada (como registrar una venta junto con su detalle, impactar el stock y registrar pagos) resida en procedimientos almacenados para garantizar la atomicidad y centralización de las reglas de la vinoteca.

Protección de datos históricos: Se estableció una regla estricta dentro de sp_eliminar_registro para prohibir explícitamente el borrado de registros en tablas transaccionales o históricas (venta, detalle_venta, venta_pago, historial_precio, vino_cepa), permitiendo operaciones de eliminación únicamente en entidades maestras validadas.

Trazabilidad de precios: Se estructuró el procedimiento sp_actualizar_precio_vino para que cualquier modificación de valor de un producto quede registrada automáticamente en la tabla de historial con su respectiva marca de tiempo y usuario responsable.

## 3. Problemas o dificultades identificadas

Incompatibilidades en el manejo de excepciones: Las diferencias entre el control de errores basado en manejadores locales y SIGNAL SQLSTATE de MySQL frente al modelo estructurado de bloques TRY...CATCH y la función ERROR_NUMBER() en SQL Server (como el atrapado del error de clave foránea número 547).

Generación y obtención de IDs autoincrementales: La adaptación de la función LAST_INSERT_ID() de MySQL al equivalente en T-SQL SCOPE_IDENTITY() para recuperar correctamente el identificador generado en la inserción de tablas maestras.

Sentencias SQL dinámicas: La necesidad de adaptar las consultas dinámicas de validación y borrado de registros utilizando sp_executesql y QUOTENAME() en lugar de las sentencias preparadas nativas de MySQL (PREPARE / EXECUTE).

## 4. Soluciones o propuestas realizadas


Se reescribieron los manejadores de errores de los procedimientos para interceptar correctamente los códigos de violación de restricciones de SQL Server y retornar mensajes claros y controlados al usuario mediante excepciones personalizadas con THROW.

Se adaptó la sintaxis completa de los 5 procedimientos almacenados para asegurar su correcta compilación y ejecución en SQL Server Express mediante el uso del comando GO y la validación previa de existencia de objetos con OBJECT_ID.

Se estructuró un set de pruebas secuenciales con instrucciones EXEC para validar el flujo completo de ventas, pagos, control de stock y actualizaciones de precios.
